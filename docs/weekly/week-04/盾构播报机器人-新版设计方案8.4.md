# 盾构播报机器人新版设计方案8.4

> 课题：隧道掘进智能体  
> 模块：盾构播报机器人 / 掘进实时播报智能体  
> 负责人：王英杰  
> 版本：8.4  
> 说明：本文在第三周《盾构播报机器人新版设计方案》基础上补充判断机制与控制效果评价方法，并用【改进】标注新增或调整内容。

## 1. 方案概述

盾构播报机器人面向盾构司机、现场技术人员和管理人员，承担“每环完成后主动说明、下一环开始前主动提醒、出现风险时主动提示”的高频服务能力。第三周设计在第二周“环总结 + 安全警示”基础上进一步调整，播报内容从字段罗列转向面向施工交流的短句式、分层式表达。

【改进】本版按照“双类播报结构”调整：将原“总结型”和“预报型”整合为“环总结播报”，将原“安全警示型”调整为因异常或突发情况触发的“安全预警播报”。

| 模板 | 主要目的 | 输出形式 |
| --- | --- | --- |
| 环总结播报 | 在前一环推进完成后，说明上一环完成情况、控制效果、安全状态概述和下一环关注方向 | 简约版、详细版 |
| 安全预警播报 | 在异常值、突发情况、报警位触发或超出安全阈值时，提示风险对象、触发依据和人工判断边界 | 简约版、详细版 |

程序采用 Python 实现，直连读取 MySQL 实时数据库。`mb_data_auto` 作为实时数据表，程序读取实时数据；`mb_data_his_auto` 作为历史数据表，用于安全阈值参考。

【改进】本版方案重点补充并落实三类机制：

| 改进目标 | 说明 | 当前处理 |
| --- | --- | --- |
| 触发条件明确化 | 说明何时触发环总结、何时触发安全预警 | 增加“前一环完成判断”和“异常触发判断” |
| 控制效果评价 | 比较“控制目标 / 期望效果”和实际控制结果 | `config_target_manage`  |
| 输出结构调整 | 将总结型和预报型合并为“环总结播报”，将安全型调整为“安全预警播报” | 已按双类结构调整 |

## 2. 数据输入与处理口径

### 2.1 数据来源

| 表 | 作用 | 使用方式 |
| --- | --- | --- |
| `mb_data_auto` | 实时数据表 | 读取实时数据作为主要目标数据 |
| `mb_data_his_auto` | 历史数据表 | 参考历史数据计算连续参数关注阈值和严重阈值等指标 |
| `config_target_manage` / `控制目标表.sql` | 控制目标配置表 | 【本次改进】用于比较预期控制目标与实际控制效果 |

真实应用中，播报机器人应对接盾构管控平台实时产生的掘进数据。当前 SQL 文件和本地 MySQL 数据库用于开发、测试和字段理解。

### 2.2 加工指标

模板不直接堆叠字段，而是将实时数据加工成施工人员更容易理解的结论。

| 加工指标 | 数据来源概括 | 用途 |
| --- | --- | --- |
| 掘进完成情况 | 环号、时间、里程、推进净行程 | 判断播报目标环，说明完成状态 |
| 工况概况 | 推进速度、总推力、刀盘扭矩、土压 | 说明本环关键施工状态 |
| 控制效果 | 前后端姿态偏差、推进节奏、土压和负载变化 | 生成“总体稳定 / 存在关注项”等表达 |
| 安全状态 | 报警位、历史阈值、连续参数是否越限 | 生成正常、关注、警示等提示 |
| 下一环关注项 | 上一环风险延续、实时状态、地质/线型/自动驾驶率占位 | 形成下一环启动前提醒 |

【改进】控制效果指标增加“目标-实际对比”口径，优先考虑以下对象：

| 评价对象 | 目标来源 | 实际来源 | 说明 |
| --- | --- | --- | --- |
| 推进速度 | `speed_start`、`speed_end` | 实际推进速度或速度设定字段 | 实际速度字段仍需确认 |
| 刀盘扭矩 | `torque_start`、`torque_end` | 刀盘扭矩实际值 | 可比较均值、最大值或稳定区间 |
| 总推力 | `thrust_start`、`thrust_end` | 总推力实际值 | 实时快照中若为 0，需判断是否为无效值 |
| 油压/油压差 | `oil_pressure_start/end`、`oil_pressure_diff_start/end` | 推进分区油压及油压差 | 实际油压字段对应关系待确认 |
| 姿态控制 | 水平/高程目标位置及偏差范围 | 前后端水平、垂直姿态偏差 | 本轮评价重点，可输出姿态控制效果结论 |

注：自动驾驶实现率、地质情况、线型情况、正式安全阈值、环完成标准和安全事件类型仍需进一步确认。

## 3. 播报触发条件

### 3.1 推荐触发逻辑

| 触发方式 | 说明 | 优先级 |
| --- | --- | --- |
| 环号变化触发 | 当实时表环号由 N 变化为 N+1 时，判定 N 环已完成，触发 N 环总结播报 | P0 |
| 推进净行程触发 | 当推进净行程达到接近一环长度且状态趋于稳定时，辅助判断当前环是否已完成 | P1 |
| 报警事件触发 | 报警位触发或连续参数达到关注阈值时，立即生成安全预警播报 | P0 |
| 人工或中枢触发 | 司机、中枢或管理端请求指定环播报，用于复盘、补报或安全核对 | P1 |

当前程序读取实时表数据生成播报，后续联动时，可在中枢或数据服务层增加环号变化监听，形成自动触发机制。

### 3.2 【改进】前一环完成判断

环总结播报的核心触发条件明确为“前一环推进完成”。在现有数据条件下，可优先采用环号变化判断：

```text
当实时数据中的环号由 N 更新为 N+1 时，系统判定第 N 环已推进完成，触发第 N 环环总结播报。
```

建议判断链路如下：

| 判断项 | 判断方法 | 当前状态 |
| --- | --- | --- |
| 主判断：环号变化 | 比较上一次读取的 `AVBA10` 与当前 `AVBA10`，若由 N 变为 N+1，则判定前一环完成 | 可实现，需要保存上一轮状态 |
| 辅助判断：推进净行程 | 检查 `ATBA02` 是否达到一环完成所需行程 | 阈值待确认 |
| 辅助判断：时间稳定 | 环号变化后等待实时数据稳定，避免刚切环时关键字段未刷新 | 需要轮询或状态缓存 |
| 重复播报控制 | 记录已播报环号，避免同一环重复生成环总结 | 可实现 |

需要补充或确认：

| 缺失项 | 影响 |
| --- | --- |
| 一环完成行程标准 | 影响 `ATBA02` 是否可作为辅助触发条件 |
| 实时表刷新频率 | 影响环号变化和突变判断的可靠性 |
| 是否存在工序状态字段 | 影响“推进完成”和“拼装完成”等状态区分 |
| 环号变化是否一定代表上一环完成 | 影响主触发条件是否需要二次校验 |

### 3.3 【改进】安全预警触发

安全预警播报从“每环固定提示”调整为“异常情况触发”。异常情况包括异常值、突发状况、报警事件和超出安全阈值等。

| 异常来源 | 判断方法 | 当前状态 |
| --- | --- | --- |
| 报警位触发 | 读取土压异常、刀盘扭矩注意、刀盘回转异常、滚动异常、非常停止等报警位 | 已具备初步字段 |
| 超出安全阈值 | 总推力、刀盘扭矩、土压差、姿态偏差等超过关注或严重阈值 | 当前使用历史统计临时阈值 |
| 参数突变 | 与上一快照、上一环均值或历史范围相比变化过快 | 需要连续实时数据或状态缓存 |
| 数据异常 | 关键字段缺失、时间不刷新、环号异常、关键参数明显无效 | 可作为数据质量预警 |
| 现场突发状况 | 异响、渗漏、管片拼装异常、人工反馈异常等 | 需要司机反馈或中枢输入 |

建议安全预警分级：

| 等级 | 触发条件 | 播报处理 |
| --- | --- | --- |
| 正常 | 未触发报警位，关键参数未超阈值 | 不单独触发安全预警，可在环总结中简要说明 |
| 关注 | 单项指标超过关注阈值，或接近控制目标边界 | 输出关注级提示 |
| 警示 | 严重报警位触发、多项指标异常或超过严重阈值 | 立即触发安全预警 |
| 数据异常 | 关键数据缺失、长时间不刷新或明显无效 | 输出数据核对提示 |

需要补充或确认：

| 缺失项 | 影响 |
| --- | --- |
| 正式安全阈值来源 | 决定关注/警示等级是否可作为工程规则 |
| 各报警位完整含义和严重程度 | 决定安全预警优先级 |
| 突发状况定义 | 决定突变类预警如何计算 |
| 人工反馈入口 | 决定现场突发情况能否进入播报链路 |

## 4. 控制效果分析

【改进】控制效果分析应从“实际工况描述”升级为“目标/期望控制效果与实际控制效果对比”。 `config_target_manage` 可作为评价依据。

### 4.1 分析流程

建议流程如下：

```text
读取目标表 -> 按环号匹配目标记录 -> 读取实际掘进数据 -> 计算实际控制结果 -> 比较目标区间与实际结果 -> 生成控制效果结论
```

| 步骤 | 说明 |
| --- | --- |
| 目标匹配 | 根据目标环号查找 `ring_start <= ring_no <= ring_end` 的控制目标记录 |
| 实际提取 | 从实时表或历史表提取该环的实际速度、扭矩、推力、土压、油压、姿态偏差等 |
| 偏差计算 | 判断实际值是否位于目标范围，必要时计算偏差比例 |
| 结果表达 | 输出“控制效果良好 / 基本稳定 / 需要关注 / 偏离较大 / 暂无法评价” |

### 4.2 评价对象

本版不展开所有字段细节，后续优先围绕以下对象调整：

| 评价对象 | 评价重点 |
| --- | --- |
| 速度控制 | 实际推进速度是否处于目标速度区间 |
| 负载控制 | 总推力、刀盘扭矩是否处于目标或合理范围 |
| 土压/油压控制 | 土压均衡性、油压和油压差是否处于目标范围 |
| 姿态控制 | 水平、高程、前后端偏差是否符合目标或允许偏差 |
| 安全状态 | 是否同时存在报警位、超阈值或突变情况 |

### 4.3 评价等级

| 等级 | 判断口径 | 播报表达 |
| --- | --- | --- |
| 良好 | 主要指标位于目标范围内，姿态偏差未扩大，未触发报警 | 控制效果良好 |
| 基本稳定 | 大部分指标符合目标，个别指标轻微偏离 | 总体稳定，局部需关注 |
| 关注 | 关键指标接近或超过目标边界，但未达到严重阈值 | 存在偏离，需重点观察 |
| 警示 | 多项指标偏离或触发严重报警/严重阈值 | 偏离较大，请现场人员介入判断 |
| 暂无法评价 | 目标表未匹配、字段缺失或实际值无效 | 数据或目标缺失，暂不输出确定性评价 |

## 5. 三类播报模板调整思路

### 5.1 总结型

**原目的**：在上一环完成后，用短句说明本环关键工况、控制效果和需要现场补充记录的问题。

【改进】总结型中增加触发依据和控制效果评价：

| 调整点 | 说明 |
| --- | --- |
| 触发依据 | 明确由“前一环推进完成”触发，优先通过环号变化判断 |
| 控制效果 | 增加目标-实际对比结论，如速度、负载、姿态控制效果 |
| 安全状态 | 若未触发异常，仅在环总结中简要说明“未见明显异常” |

示意话术：

```text
第 {ring_no} 环推进完成。本次播报由环号变化触发。
本环推进节奏{drive_result}，姿态控制{posture_result}，负载与土压{load_pressure_result}。
根据控制目标对比，{target_evaluation}。
下一环开环阶段请重点关注{next_attention_items}。
```

### 5.2 预报型

**原目的**：在下一环启动前，结合上一环状态提醒需要提前关注的工况、地质、线型和安全延续项。

【改进】预报型暂不强化为确定性预测，主要作为环总结之后的下一环关注提醒：

| 调整点 | 说明 |
| --- | --- |
| 预报边界 | 地质、线型、自动驾驶率数据未接入时不输出确定性结论 |
| 关注来源 | 下一环关注项优先来自上一环控制效果、异常延续和现场风险 |
| 与总结型关系 | 后续可考虑并入“环总结播报” |

### 5.3 安全警示型

**原目的**：当报警位触发或连续参数超过关注阈值时，提示风险对象和现场判断边界；未触发风险时，输出正常状态和下一环关注项。

【改进】安全警示型建议调整为异常触发的“安全预警播报”：

| 调整点 | 说明 |
| --- | --- |
| 触发方式 | 由报警位、超阈值、突变、数据异常或现场突发情况触发 |
| 正常情况 | 正常状态不再单独生成安全预警，只在环总结中简要说明 |
| 安全边界 | 仍需保留“不代表最终安全裁决，请现场人员介入判断” |

示意话术：

```text
安全预警：第 {ring_no} 环{risk_object}触发{risk_level}级提示，原因是{trigger_reason}。
请现场人员介入判断，并核对{check_items}。该条播报不代表最终安全裁决。
```

## 6. 补充方案：调整为“环总结播报 + 安全预警播报”

【改进】考虑将总结型和预报型整合为“环总结播报”，将安全型调整为因突发情况触发的“安全预警播报”。该思路暂作为补充方案记录，不直接替代原三类模板。

| 当前结构 | 补充方案结构 | 说明 |
| --- | --- | --- |
| 总结型 | 环总结播报 | 合并上一环完成情况、控制效果评价和下一环关注方向 |
| 预报型 | 环总结播报 | 作为环总结中的“下一环关注”部分 |
| 安全警示型 | 安全预警播报 | 只在异常、报警、超阈值、突发或数据异常时触发 |

补充方案的优点：

| 优点 | 说明 |
| --- | --- |
| 播报边界更清楚 | 正常情况下输出环总结，异常情况下输出安全预警 |
| 减少安全提示疲劳 | 未出现异常时不单独生成安全预警 |
| 更贴近现场流程 | 环完成后总结，异常发生时预警 |

补充方案的风险：

| 风险 | 说明 |
| --- | --- |
| 需要可靠触发机制 | 若异常判断不充分，可能漏报 |
| 需要重构输出文件 | 程序输出可能从三类文件调整为两类文件 |
| 下一环预报内容会被压缩 | 需要确认下一环预报是否仍需独立保留 |

## 7. 后续对接事项

| 事项 | 说明 |
| --- | --- |
| 环完成触发 | 需要确认实时表环号变化、推进净行程或工序状态哪个作为自动触发源 |
| 安全预警触发 | 需要确认报警位、正式安全阈值、突变规则和现场突发事件类型 |
| 控制效果评价 | 需要确认控制目标表与实际字段的对应关系，尤其是速度、油压、姿态字段 |
| 地质与线型数据 | 下一环预报中的地质、线型仍需接入正式资料或知识库 |
| 自动驾驶实现率 | 需要统一口径，可按自动驾驶有效时长、自动推进距离或自动控制执行记录计算 |
| 中枢与 APP 联动 | 需要确认播报文本由播报机器人直接输出，还是由中枢统一改写后展示 |
| MCP 工具化 | 若后续封装为工具集，需要明确工具输入、输出、错误处理和只读数据库访问边界 |

## 8. 当前结论

本版方案不推翻第三周新版方案，而是在原有三类模板基础上补充判断机制和评价方法。后续最优先的改进方向是：

1. 用环号变化判断前一环推进完成，作为环总结播报主触发条件。
2. 将安全警示调整为异常触发，异常来源包括报警位、超阈值、突变、数据异常和现场反馈。
3. 引入 `控制目标表.sql`，建立控制目标与实际控制效果的对比评价。
4. 对缺失数据和未确认规则保持空缺或待确认表达，不输出无依据结论。
5. 记录“双类播报结构”作为补充方案，待确认后再决定是否正式调整模板与程序输出。
