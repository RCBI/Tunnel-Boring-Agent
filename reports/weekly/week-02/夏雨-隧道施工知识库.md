## 1. 本周结论摘要

本周完成 WeKnora 与 Sirchmunk 两种开源路线的调研和阶段性选型。WeKnora 适合当前需要的稳定知识分类、权限治理和重复问答，且本机已完成部署，因此作为第二周实施主链路；Sirchmunk 采用无预索引搜索和自演进 KnowledgeCluster，更适合动态原始资料、跨文件证据发现和深度研究，后续将通过同题测试评估组合方式。已形成包含两层文件结构、差异化知识抽取、问答检索路由、风险因果推理、知识图谱试点和控制安全边界的《知识管理设计方案》。当前尚未配置可用的 Embedding API 或本地模型，向量检索与风险推理仍待实测。

## 4. 关键设计与决策

| 决策或问题 | 当前选择 | 选择依据 | 影响或代价 |
| --- | --- | --- | --- |
| 主平台 | WeKnora | 具备知识库、标签、混合检索、引用、权限和任务治理，且已部署 | 需要完成解析和向量化，首次入库耗时 |
| Sirchmunk 定位 | 与 WeKnora 互补的无预索引检索路线 | 支持 FAST/DEEP、证据采样和 KnowledgeCluster 复用，适合动态资料与深度研究 | 尚未在本机验证中文工程资料效果，后续做同题对照测试 |
| 模型路线 | Ollama + `bge-m3` | 可本地运行，不需要付费 API | 占用本机资源，需单独安装测试 |
| 导入策略 | 每批 10～20 份 | 本次全量导入造成数千任务积压 | 首批建设速度降低，但便于检查质量 |
| 查找逻辑 | 按业务目标、工况和权威等级路由 | 意图分类不能直接形成业务判断 | 需要维护规范、案例、论文和项目数据的不同模板 |
| 风险推理 | “现象—原因—后果—验证—措施”证据链 | 决策必须可解释、可反证、可追溯 | 缺少关键工况时先追问，不生成候选值 |
| 控制边界 | 候选指令经判断智能体审核和司机确认后下发 | 符合原项目的人机交互与安全定位 | 知识库和大模型不能绕过确定性规则直接控制 PLC |

## 5. 方案一致性

方案调研对应 WeKnora/Sirchmunk 两种不同索引时机和知识组织方式的比较；当前先实施 WeKnora 是基于已有部署与本周交付范围的阶段性选择，不构成平台通用排名。知识管理方案对应文件结构、标签、差异化抽取、检索路由、风险推理和知识图谱试点；基于资料开发对应首批资料映射及实施步骤。当前尚未完成 Embedding API 或本地模型配置，也未下载并核验正式规范原文；下周完成模型配置、小批检索和第一条风险链验证。
